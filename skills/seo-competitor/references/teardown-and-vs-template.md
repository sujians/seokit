# B2B 竞品拆解与选型对比模板

## 样本选择与取证

- 指定 URL 按用户范围取样，先去重并保留原顺序。只给关键词时，结合用户要求和档案确认一个目标国家和搜索语言。只知道大区或有多个候选市场时，确认本次搜索范围。`location` 用 DataForSEO 国家名称或代码，`language_code` 用服务支持的语言代码，例如 `en`。默认桌面，用户指定设备时沿用其选择。
- 先调用 `seokit_dataforseo_serp({ location, language_code, keywords: [keyword], top_n: 10, device, dry_run: true })`。`available: true` 且 `sandbox: false` 时沿用相同参数执行，省略 `dry_run`。沙盒数据只供集成测试，按技能的无排名数据流程获取竞品 URL。如费用超过 USD 0.50，由 Pi 工具弹窗取得确认。记录查询、国家、语言、设备、`observedAt` 和可用的 `searchUrl`，以及取样所用的自然名次 `rank`。用户指定链接时标明来源，名次留空。
- 从 `results[].organic` 按自然名次选取同一产品、工艺或应用的 1–3 个可用页面。排除本项目站点、重复落地页、`unresolved_goto: true` 和无法验证的跳转入口。优先不同供应商的产品、工艺、应用或选型页。目录、经销商或媒体若与采购任务有关，可作为渠道或内容参照，注明身份。用最终 URL 再去重，记录候选不足和被跳过结果的原因。采样范围限选中的页面和与具体结论直接相关的公开证据。

给每个样本绑定一个绝对 HTTP(S) `url`，在同一个 Pi `codemode` 脚本中串联工具。分开调用可保留其他样本的结果。

```js
let page;
try {
  page = await tools.seokit_fetch_page({ url });
} catch (error) {
  return { url, analyzed: false, fetchError: String(error) };
}
const { html, status, contentType, truncated } = page;
const response = { requestedUrl: url, finalUrl: page.url, status, contentType, truncated };
const isHtml = /^(?:text\/html|application\/xhtml\+xml)\b/i.test(contentType ?? "") ||
  (!contentType && /^\s*(?:<!doctype\s+html|<(?:html|head|body)\b)/i.test(html));
if (status < 200 || status >= 300 || !isHtml || !html.trim()) {
  return { ...response, analyzed: false };
}
const [seo, geo] = await Promise.allSettled([
  tools.seokit_parse_seo({ url: page.url, html }),
  tools.seokit_score_geo({ html }),
]);
return {
  ...response,
  seo: seo.status === "fulfilled" ? {
    title: seo.value.title,
    headingCounts: seo.value.headingCounts,
    headings: seo.value.headings.filter(({ level, text }) => level <= 3 && text)
      .slice(0, 30).map(({ level, text }) => ({ level, text: text.slice(0, 200) })),
    links: seo.value.links,
    baseUrl: seo.value.baseUrl,
  } : { error: String(seo.reason) },
  geo: geo.status === "fulfilled" ? geo.value : { error: String(geo.reason) },
};
```

- 使用可用的网页阅读器核对正文和文档。也可在抓取脚本中按相关标题、型号或标签从同一响应输出少量上下文，例如参数表行、证书链接和表单入口。用最终 URL 或适用的 `baseUrl` 解析相对链接，核实链接标签、位置与去向。计数、摘录、匹配结果和搜索摘要仅支持其实际显示的内容。
- 遇到截断、脚本壳、受限响应或工具错误时，记录已取得的证据与未验证项目。`codemode` 不可用时，可记录普通调用的 HTTP 结果并用可用的网页阅读器补证，注明方式及限制。抓取摘要不能充当完整 HTML。评估 CTA 可查看公开入口及可见字段，禁止提交表单、触发询价或访问登录后的内容。

## 逐页拆解维度

| 维度 | 核对内容 | 可记录的证据 |
| --- | --- | --- |
| 页面类型与结构 | 识别产品、品类、工艺能力、行业应用、vs 或替代页。对应工程选型、采购询价或供应商审核。 | 标题、H1–H3、正文模块顺序，区分正文与导航及页脚。 |
| 参数透明度 | 查型号、材料牌号、尺寸和公差、性能与测试条件、规格表或图纸、MOQ 和交期。区分公开值、选项与询价确认项。 | 带单位与适用范围的表行、产品或文档链接、版本或核对日期。 |
| 认证与信任背书 | 核对证书主体、厂址、覆盖产品、范围及有效期。区分标准引用、企业声明、检测报告和第三方认证，注明案例的适用条件。 | 证书编号及发布方记录、页内声明或公开案例。仅有徽标或声明时记为该站披露，独立核验状态留待确认。 |
| CTA 路径 | 找到报价、样品、图纸、选型支持或联系入口。记录位置、去向、可观察的步骤和字段，以及图纸上传或必填项是否可见。 | CTA 原文与公开目标、页面锚点、可见字段及核对范围。 |
| 内链形态 | 识别导航、面包屑、正文推荐和页脚，核对是否通向产品系列、工艺、资料、案例和询价。 | 解析器给出的全页链接计数，加代表性锚文本、位置与去向。 |
| GEO 可引用度 | 查可独立引用的结论、带单位和条件的参数、结构化表格或清单、来源标记。 | `seokit_score_geo` 启发式分数与直接回答、结构、证据、清晰度信号，以及短摘录。分数描述样本 HTML，实际平台引用须另有观测。 |

每项记录来源 URL、核对日期和可定位的段落、表格或文件。可用「已观察」「仅站方声明」「样本未见」「未验证」描述证据状态。「样本未见」只用于相关公开页面范围内可核对的项目。报错、截断、登录限制和动态内容造成的缺口使用「未验证」。

## 差距报告

1. **范围和样本。** 写明主题、市场、语言、买家任务、目标项目上下文。列出查询或指定来源、输入和最终 URL、自然名次（如有）、页型及抓取状态。说明同类本站页面和档案是否能提供基线。
2. **逐页证据。** 按维度表记录观测、限制和可追溯来源。若有报告级结论仅源自单页或特定版本，在结论处保留范围。
3. **改进顺序。** 按对选型、资质审核和询价的影响排序。每项说明竞品页观察、同类本站证据或待核对项、影响、建议落点、依赖和验收方法。示例是「在型号页补充工况与单位，发布后复查规格表与数据表一致」。本站无基线时写机会和待核对项，避免断言本站缺失。
4. **证据缺口。** 写明哪些规格、认证、CTA 或链接仍需验证，以及可以补查的具体文件或信息。将对比稿需要的待核验事实留在这里或草稿的编辑备注。

## vs 对比页或选型替代页

1. **标题与直接结论。** vs 页用「[型号 A] vs [型号 B]：面向 [工况/采购任务] 的选型比较」。替代页用「[对象] 的选型替代方案：按 [工况/要求] 比较」。首段给出各方案适用条件和应向供应商确认的事项。公开披露与自有方案的关系，陈述资料核对日期及测试依据。只有实际证据支持时才描述实测。
2. **比较范围及矩阵。** 说明型号和版本、市场、工况、配置及可比条件。为各方案采用同一组与决策相关的行，如材料与公差、性能与测试方法、合规范围、接口与替换验证、采购条件。每个重要数据项附可定位的来源。公开报价只有在币种、数量、配置、交付条件和时点可以对照时才比较。不可比的值分别标注条件，未知项写「公开资料未见」「需供应商确认」或「资料未核实」。

   | 选型条件 | 方案 A（型号/配置） | 方案 B 或其他可选方案 | 可比条件与核对事项 |
   | --- | --- | --- | --- |
   | [指标与单位] | [公开值、适用工况、来源] | [公开值、适用工况、来源] | [共同条件或需确认项] |

3. **按买家场景解释取舍。** 工程侧关注适配、验收和验证成本，采购侧关注供货、文档和询价条件。替代页为每个方案给出适用场景、切换时要核验的接口、质量文件或样件试验；不承诺互换或兼容性。把充分条件写成可引用的句子，并保留合理的竞品优势及限制。
4. **下一步与来源。** 提供读者可执行的核对清单，例如提交图纸、确认公差和试验工况、索取对应型号的证书或样件。需要 CTA 时使用已核实的本站采购入口及描述性链接。统一列出资料名称、版本、核对日期和公开 URL，引用放在对应结论或表格项附近。发布前清除编辑备注并重新核对会变动的事实。

优先查产品厂商规格书、制造商页面、标准发布方、监管机构或认证数据库。公开标准、材料性质与试验依据须在线核验和引用。涉及自家企业的性能、资质、产能和商务条件，先用适用档案或用户材料核实，并核对档案的 `terminology.banned_phrases[].phrase`。需要公开佐证的对比主张仅在可引用时写入正文。缺证据在编辑备注标 `[TODO: …]`，正文可用条件化的采购问题表达。禁止捏造缺陷、测试、证书或评价，禁止暗示未经证实的关联或背书。只在已核实主体且存在共同选型任务时起草具名 vs。

## 文件命名与复核

- 从关键词生成 slug。仅提供 URL 时，用首条指定链接的主机与路径作为基础，忽略查询和片段。按 Unicode NFKC 规范化并转小写，将连续的非字母、数字及组合标记替换为单连字符，去掉首尾连字符，截取最多 48 个 Unicode 码点再去掉尾部连字符；空值用 `competitor`。
- 确认报告和草稿的目标位于 `audits/` 与 `drafts/`。检查两个命名目标，遇已有文件时使用同一可用后缀 `-2`、`-3` 等，保留已有成果。读回检查报告中的样本、来源、缺口与拟议动作，及草稿中的可比条件、来源与中立表述。确认后返回实际路径。
